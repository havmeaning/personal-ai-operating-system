# Architecture

P.Ai.O.S. is organized as a proof system rather than a warehouse.

```text
Inputs
  |
Capture and structure
  |
Analysis and decision
  |
Execution
  |
Reports and evidence
  |
Doctrine and reusable assets
  |
Back into the next operation
```

## Repository Architecture

| Area | Purpose |
|---|---|
| `docs/` | Method documentation. |
| `examples/` | Worked demonstrations. |
| `templates/` | Reusable operating artifacts. |
| `evidence/` | Claims, evidence ledger, and source manifest. |
| `validation/` | External-transfer testing package. |
| `case-studies/` | Bounded case studies. |
| `reports/` | Canonical public reports and summaries. |
| `assets/` | Small visual explanations. |

## Design Principle

Someone should be able to inspect the method, check the claims, use a template, and understand what remains unproven without reading the entire source archive.
